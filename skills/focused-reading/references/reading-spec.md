# 阅读输出规范

专注阅读的目标:只读和用户问题相关的材料,只输出能推进当前问题的结论。

## 输出模板

### 默认回答

```markdown
**结论**
[直接回答用户问题]

**依据**
- `path:line`: [关键事实]

**不确定**
- [缺失材料或待验证点]

**附带发现**
- [最多 1-3 条,没有就省略]
```

### 摘要

```markdown
**核心摘要**
- ...
- ...
- ...

**和你问题相关**
- ...

**下一步阅读入口**
- `path`
```

### 给下一个 agent 读

```markdown
Read first:
- `path`

Known facts:
- ...

Open questions:
- ...

Do not assume:
- ...
```

## 图文/网页材料

读取图文或网页材料时不要只看正文。保留来源、图片顺序、可见信息和可复用素材索引,方便后续归档、复核或二次使用。

提取顺序:

1. 来源:URL、标题、作者/账号、发布时间、抓取时间。
2. 文本:标题、正文主张、列表、价格/数字/限制条件。
3. 图片:每张图的可见内容、顺序、和正文的对应关系。
4. 链接/附件:只记录和用户问题相关的链接。
5. 可信度:缺失、模糊、疑似广告或无法验证的信息。

输出时只放和用户问题相关的部分。完整素材清单只有在用户要求归档或复用时才写入文件。

## PR / 代码阅读

- 先读 diff,再读被调用点和测试。
- 不扫全仓库,除非当前问题需要。
- 结论必须落到具体文件、函数、行为或测试缺口。
- 不把 review 变成重构计划。

## 日志阅读

- 先定位时间、错误级别、请求/任务 ID。
- 区分根因、症状和噪声。
- 不把没有证据的猜测写成结论。

## 禁止模式

- 不要顺手提出实现方案、重构建议、工时、优先级。
- 不要把一个阅读问题拆成多轮决策树。
- 不要把整篇材料复制给用户。
- 不要把未读到的内容说成事实。
- 不要为了显得全面而阅读无关目录。
- 不要在用户只问“哪里写了”时输出长篇解释。
