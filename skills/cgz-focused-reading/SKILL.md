# 专注阅读

读取材料时只读和用户问题相关的内容，只输出能推进当前问题的结论。

## 入口与依据

判定依据全部写在 [阅读输出规范](references/reading-spec.md)。该文件分五大节：

1. **五原则** —— 先锚定再读、不扩范围、区分事实 / 推断 / 不确定、旁支最多 3 条、不把阅读题答成实现题。
2. **五维度** —— 输出前自检：范围 / 证据 / 区分 / 形态 / 语言。
3. **五心理学** —— 失败模式的认知机制：全景偏好 / 锚定 / 沉没成本 / 教学冲动 / 一致性偏差。
4. **对话严苛规则** —— 允许 / 禁止句式、禁止开场、禁止跨题扩展。
5. **语言纯化规则** —— 中文段落不夹裸英文、英文模板保持纯英文、文件名命令名保留原文。

处理长文档、PR、日志、网页、图文或需要固定输出结构时，立刻读取该规范。

## 最小流程

内部先确认：

```text
用户要我读什么？
用户真正问的问题是什么？
本次输出需要：结论 / 摘要 / 风险 / 对比 / 提取 / 定位？
哪些材料必须读？哪些只是可能相关？
```

材料或问题不明确时只问一个澄清问题。

## 范围控制

| 用户请求 | 必须读取范围 |
| --- | --- |
| 看这个文档讲了什么 | 只读该文档，输出核心结论 |
| 这段 PR 有没有问题 | 读 diff + 相关测试 / 调用点，不扫全仓库 |
| 帮我理解上下文 | 读用户指定上下文 + 最近相关文档，不扩到全项目 |
| 从图文 / 网页里提取信息 | 只提可见事实；细则要求时再读 reference |
| 找某个答案 / 字段 | 优先检索，直接返回位置和答案 |

长材料先扫目录、标题、索引、首尾段、代码入口；命中相关问题再深入。

## 默认输出

```markdown
**结论**
[直接回答用户问题]

**依据**
- `path:line`：[关键事实]

**不确定**
- [缺失材料或待验证点]

**附带发现**
- [最多 3 条；没有就省略]
```

## 何时切到归档

阅读本身只负责回答当前问题。出现以下情况立刻停止扩展阅读，建议切到 `cgz-archive-session`：

- 用户说「归档 / 收尾 / 给下次看 / 保存上下文 / 交接」。
- 本轮读了多个文档、网页、PR、日志或长聊天。
- 输出里已包含多个路径、结论、未决问题或后续入口。
- 图文 / 网页素材后续可能复用。
- 用户问题已答完，但阅读结果会影响后续工作。
- 对话开始从「读材料」变成「讨论方案 / 做决策 / 安排下一步」。

只有用户确认或显式要求归档时才写文件。
