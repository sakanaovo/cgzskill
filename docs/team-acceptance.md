# 团队记忆人工验收清单

**状态：以下端到端场景尚未执行。** 本仓库是宿主 agent 按需遵循的说明规则，不含初始化程序、后台监听或 Git 自动合并器。`tests/test_team_contract.py` 只校验模板语法及规则文本一致性，不是运行时验收，不能证明宿主实际按协议处理并发。

在隔离的临时测试项目中手工调用 skill，保存前后文件清单、内容摘要及 Git 状态作为证据。禁止使用真实密钥、邮箱或未脱敏业务资料。涉及覆盖、冲突、已跟踪身份时应停下确认，而不是为完成验收绕过保护。

| 场景 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| 两个作者初始化 | 两份工作副本分别明确请求初始化并确认不同别名，再重跑一次 | 各自本地 JSON 有独立随机 `author_id`；忽略项精确为 `/.cgz/local.json`；共享模板不含作者身份；重跑不改 ID、不重复追加入口 |
| 同一作者并发会话 | 在同一工作副本同时归档两个不同会话 | 两份独立 UUID 文件；不覆盖、追加共享索引或抢写 `ai-lessons.md`；模拟目标文件已存在时重新生成 ID，原内容不变 |
| 首次身份创建竞争 | 两个会话同时发现身份缺失 | 排他创建，后到者重读有效身份；不各自覆盖；若确认的别名冲突则报告并询问 |
| 无 Git 与 worktree | 在无 Git 项目初始化；另在两个 Git worktree 初始化并归档 | 无 Git 不阻塞，分支/基线无法获取时明确空值；不同 worktree 各保留本地身份，不改全局 Git 配置、不扫描主目录 |
| 已跟踪或损坏身份 | 在测试仓库跟踪身份文件，或写入损坏 JSON 后重跑 | 报告问题并等待决定；不擅自 `git rm`、改历史或覆盖；不声称身份已被忽略保护 |
| 重复来源与复盘幂等 | 同一作者对同一天、同范围、同来源集合连续复盘；随后增加一份来源再复盘 | 相同集合且无新事实时复用原摘要；新增来源才写新 UUID 摘要；旧日报不成为新事实源，同一来源只计一次 |
| 同义、互补与矛盾 | 准备同义同范围、互补、同范围矛盾、不同范围四组来源 | 同义汇总成一条但保留全部来源；互补都保留；同范围矛盾标 `pending`；不同 scope 分别保留；不按时间/作者/多数票自动采纳规则 |
| 旧数据兼容与更正 | 使用旧单文件归档和带日期的教训，生成汇总后纠正其中一条 | 原文件和旧配置字节不变；旧来源用路径及日期定位；更正新建记录并引用 `supersedes`，不补写旧 ID、不迁移或删除历史 |
| 明确采纳团队规则 | 将候选教训交给用户或团队 PR 评审 | 未授权前不写稳定规则；明确采纳后保留来源、范围和验证状态，矛盾不能被静默当成生效规则 |

每项验收记录应标明宿主、版本、测试日期与时区、实际观察、证据路径及通过/失败/未测。静态测试通过不改变本清单的“尚未执行”状态。
