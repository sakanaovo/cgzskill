# 启动检测规范

cgz-init 的目标：在用户项目里把「记忆体系骨架」一次性落地，不擅自、不覆盖、不越界。本文件是判定依据，分五大节。

---

## 一、五原则

1. **必须先扫描后生成。** 禁止假设缺失项，必须先列出已存在 / 缺失清单。
2. **必须先询问后写入。** 用户未确认前禁止写任何文件。
3. **已存在文件禁止覆盖。** 只补缺失项；已存在但缺 cgz section 时，追加而非重写。
4. **只生成骨架。** 禁止预填业务规则、禁止预填项目偏好、禁止替用户决定语言或语气。
5. **一次性操作。** 禁止每次会话重跑；只在显式触发或自检条件满足时执行一次。

---

## 二、五维度（写入前自检）

1. **触发** —— 是用户显式要求 init，还是 agent 自检建议（建议必须经用户确认）。
2. **扫描** —— 是否完整列出已存在 / 缺失清单，并展示给用户。
3. **询问** —— 是否用单一问句问「全生成还是挑选」，禁止多问、禁止默认全生成。
4. **安全** —— 已有文件是否完整保留，追加内容是否带清晰分隔（`---` + 章节标题）。
5. **收尾** —— 回复是否 ≤ 12 行；是否包含「生成 / 保留未动 / 下一步」三段。

---

## 三、五心理学（失败模式的认知机制）

1. **全包冲动** —— agent 倾向「一键搞定」，容易覆盖已有文件或预填用户没问的内容。
2. **默认偏好** —— 把模板里的「示例规则」当成项目规则强加给用户。
3. **自动化幻觉** —— 把 init 当作 daemon，每次会话都扫，制造重复噪声。
4. **完整性焦虑** —— 把不缺的项也重写一遍，证明自己「搞全了」。
5. **越界冲动** —— 顺手装 skill、改业务代码、写测试，超出 init 边界。

---

## 四、对话严苛规则

**允许的句式**：必须 / 禁止 / 立刻 / 不得 / 只 / 一律。

**禁止的句式**：优先 / 尽量 / 建议 / 可以考虑 / 也许。

**询问必须单一**。扫描完一次只问一次：

```text
以下 N 项缺失：……。要全部生成，还是挑选？
```

禁止：

- 「我帮你建好了所有东西」类全包语
- 「你看 OK 我就开始」类模糊确认
- 在询问前展开「我接下来要做什么」的长说明

**收尾回复 ≤ 12 行**，结构固定：

```text
cgz 记忆体系已就位。

生成：
- ……

保留未动：
- ……

下一步：
- ……
```

禁止在收尾里展开新方案、补示例、给后续教程。

---

## 五、语言纯化规则

**中文段落不夹裸英文 token**：

- `bootstrap` → 启动 / 初始化
- `template` → 模板
- `skeleton` → 骨架

**英文模板字段保留纯英文，不译**（适用于生成的 `ai-lessons.md` 与 `AGENTS.md`）：

- Read first / Next / Decisions / Verified / Risks / Lessons / Trigger / Wrong / Correction / Rule

**文件名、命令名、路径、API 名一律保留原文。**

**表格里同一格不混语言。**

---

## 扫描规范

扫描必须覆盖以下项，逐项给出「存在 / 缺失」：

| 项 | 路径 | 必须 / 可选 |
| --- | --- | --- |
| 长期规则文件 | `AGENTS.md`（项目根） | 必须 |
| Claude Code bridge | `CLAUDE.md`（项目根） | 可选；仅 Claude Code 项目建议 |
| 教训日志 | `docs/ai-lessons.md` | 必须 |
| 归档目录 | `docs/archives/` | 必须 |
| 归档目录索引 | `docs/archives/README.md` | 可选；为空目录提供说明 |
| Obsidian vault 配置 | `AGENTS.md` 的 `## cgz 配置` 段里 `obsidian_vault` 值 | 必须；空值表示禁用 daily-recap |

**判断「已存在」的标准**：

- 文件存在 → 视为已存在，不重写。
- `AGENTS.md` 存在但不含 cgz section（无标题「## cgz 记忆体系」）→ 视为「部分存在」，向用户说明，询问是否追加 cgz section。
- `AGENTS.md` 有 cgz section 但 `## cgz 配置` 段缺失或 `obsidian_vault` 行缺失 → 视为「配置缺失」，询问 vault 路径后追加配置段。
- 目录存在但为空 → 视为已存在；不强行加 `README.md`，除非用户同意。

**扫描后必须列出**：

```text
已存在：
- AGENTS.md（缺 cgz section）
- docs/

缺失：
- docs/ai-lessons.md
- docs/archives/
```

---

## 生成规范

### `AGENTS.md`

**完全缺失** → 用 `assets/AGENTS.md.template` 写入项目根。先问用户 `obsidian_vault` 路径，把答案填进模板的 `## cgz 配置` 段。

**已存在且无 cgz section** → 在文件末尾追加，前置 `---` 分隔，再插入 cgz section 模板内容（含 `## cgz 配置` 段，vault 路径来自用户输入）。禁止重排原内容、禁止改动原标题。

**已存在、有 cgz section、但缺 `## cgz 配置` 段或缺 `obsidian_vault`** → 只追加配置段或在配置段补 `obsidian_vault` 行，其他内容不动。

**已存在且配置齐全** → 跳过，不动。

### `docs/ai-lessons.md`

**完全缺失** → 用 `assets/ai-lessons.md.template` 写入。

**已存在** → 跳过；不追加示例条目。

### `docs/archives/`

**目录缺失** → `mkdir -p docs/archives/`。

**目录为空** → 询问是否放一个最小 `README.md`（内容：「本目录由 `archive-session` skill 写入，每个文件是一次会话或迭代的归档。」）。

### `CLAUDE.md`（可选）

仅在用户明确是 Claude Code 项目（已有 `.claude/` 目录或 `.claude-plugin/`）时才询问是否生成。模板内容：bridge 到 `AGENTS.md`，不重复内容。

---

## 不生成的项

| 不生成 | 原因 |
| --- | --- |
| `.claude/skills/*` | `/plugin install` 的职责 |
| `~/.codex/skills/*` | 用户级安装，跨项目 |
| 任何业务代码 / 配置 | 超出 init 边界 |
| `.gitignore` 改动 | 用户的版本控制决定 |
| `package.json` / `pyproject.toml` 等 | 不属于记忆体系 |

---

## 收尾必须包含

回复 ≤ 12 行，三段固定：

1. **生成** —— 实际写入的文件清单。
2. **保留未动** —— 已存在所以跳过的文件。
3. **下一步** —— 用户接下来要做的两件事：
   - 在 `AGENTS.md` 的「项目专属规则」段填实际规则。
   - 出错 / 被纠正时按 6 步循环记录到 `docs/ai-lessons.md`。

禁止在收尾里展开新方案、补使用教程、给可选建议。
