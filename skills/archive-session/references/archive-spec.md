# 归档规范

一份合格归档必须让未来 agent 在 3 分钟内恢复上下文，且不被旧聊天噪声带偏。本文件是判定依据，分五大节：五原则、五维度、五心理学、对话严苛规则、语言纯化规则。`SKILL.md` 是入口，写归档前读这里。

---

## 一、五原则

1. **只保存事实、结论、路径、验证结果、下一步。** 不存闲聊、心理活动、过程复盘。
2. **归档不新增分析。** 不补方案、不评工时、不重排优先级。
3. **用户未确认前不写文件。** agent 自检建议归档时，必须先问。
4. **按内容分流。** 讨论归讨论，迭代归迭代，交接归交接；不塞万能文件。
5. **推断与未验证必须用标签分开。** 不可与已确认事实混写。

---

## 二、五维度（写入前自检）

1. **触发** —— 是用户显式要求归档，还是 agent 自检建议（建议必须经用户确认）。
2. **位置** —— 是否沿用项目既有约定，没有另起一套文档系统。
3. **区分** —— 已确认 / 推断 / 未验证 标签是否齐。
4. **入口** —— 下一轮 agent 是否能在 3 分钟内恢复（Read first 是否明确）。
5. **收尾** —— 回复是否 ≤ 12 行；是否未在归档完成后又展开新方案。

---

## 三、五心理学（失败模式的认知机制）

1. **完整性幻觉** —— agent 倾向把「写得长」当作「归档得好」。归档越长越没人读。
2. **复盘冲动** —— 归档时手痒补一轮「我学到了什么」，结果归档变成新分析。
3. **推测变事实** —— 推断写着写着丢掉前缀，下一轮 agent 当成事实接住。
4. **焦虑储存** —— 把「可能有用」的内容全塞进归档，长期噪声压过信号。
5. **重写历史** —— 修改归档时悄悄抹掉旧结论，让未来 agent 失去回溯线索。

---

## 四、对话严苛规则

**允许的句式**：必须 / 禁止 / 立刻 / 不得 / 只 / 一律。

**禁止的句式**：优先 / 尽量 / 建议 / 可以考虑 / 也许。

**归档收尾回复 ≤ 12 行**，结构固定：

```text
已归档。

文件：
- ……

本次保留：
- ……

下一轮先看：
- ……
```

**禁止在收尾回复里**：

- 展开新方案
- 复述归档内容
- 补一句「希望对你有帮助」
- 提工时或优先级

---

## 五、语言纯化规则

**中文段落不夹裸英文 token**：

- `handoff` → 交接
- `path` → 路径
- `findings` → 发现 / 问题清单

**英文模板字段保留纯英文，不译**：

- Read first / Do not change / Current state / Bug / task / Acceptance / Run
- Goal / Changed / Verified / Decisions / Risks / Next / Open questions

**文件名、命令名、API 名、字段名一律保留原文。**

**表格里同一格不混语言。**

---

## 必须包含

- **标题**：日期 + 主题。主题用用户目标命名，禁止用「杂项 / 总结 / 聊天记录」。
- **触发原因**：收尾 / 跑偏 / 交接 / 完成迭代 / 长上下文压缩。
- **当前目标**：用户真正要完成什么，1-2 句写清。
- **已确认事实**：只写读到、验证过、用户确认或代码实际存在的内容。
- **关键路径**：文件、链接、命令、测试输出、截图或素材位置。
- **决策记录**：决定 + 为什么，不展开备选方案历史。
- **未决问题**：每条都能被行动。
- **下一步入口**：未来 agent 应该先读什么、先跑什么、先问什么。

---

## 必须区分

用标签分开，禁止混写：

```markdown
## 已确认

## 推断

## 未验证

## 下一步
```

不要把推断写成事实。不要把「可能有用」的想法写成待办。

---

## 粒度

- 一条归档记录只服务一个主题或一轮迭代。
- 多主题混在一起时必须先拆主题；不能拆时，在文档内用清晰小节隔开。
- 每条 bullet 必须能独立被执行或验证。
- 原文只保留必要短摘录；长材料用路径、链接或附件索引。

---

## 语言风格

- 用短句、事实句、命令式下一步。
- 禁止心理活动、过程复盘、客套话。
- 禁止「我认为很重要」类无证据判断。
- 禁止大段表格；表格只用于路径索引、测试结果、决策记录。

---

## 更新还是新建

- 同一主题当天继续推进：必须追加到已有归档。
- 新主题、新结论组或新交接对象：新建归档。
- 长期文档只接收稳定结论；临时讨论留在会话归档。
- 修改已有归档时只追加新小节或补充状态，禁止重写历史让旧结论失踪。

---

## 内容压缩

**只保留**：

- 用户最初目标
- 已确认的结论和决策
- 修改或阅读过的文件路径
- 关键命令、测试结果、失败样例
- 仍未验证的风险
- 下一轮 agent 应先读 / 先做什么

**必须删除**：

- 重复确认、闲聊、语气修饰
- 已被推翻的猜测（除非它解释了为什么改方向）
- 用户没要求的新方案、工时、优先级
- 大段原文复制（用路径或短摘录索引代替）

## 模板

### 讨论归档

```markdown
# 对话归档 · YYYY-MM-DD

**主题**：[一句话]
**触发原因**：[归档 / 跑偏 / 收尾 / 交接]

## 当前焦点

[本轮真正要解决的问题]

## 已确认

- ……

## 推断

- ……

## 未验证

- ……

## 下一步

- Read first: `path`
- Next: ...
```

### 迭代归档

```markdown
## YYYY-MM-DD HH:mm - [本轮迭代名称]

Goal:
- ...

Changed:
- `path`: ...

Verified:
- `command`: result

Decisions:
- ...

Risks:
- ...

Next:
- ...
```

### Handoff（交接）

```markdown
# Handoff · YYYY-MM-DD

Read first:
- `path`

Do not change:
- ...

Current state:
- ...

Bug / task:
- ...

Acceptance:
- ...

Run:
- `command`
```

## 索引规范

创建新归档文件时必须同步更新最接近的索引。没有索引时在同目录创建一个最小索引。

索引只记录：

- 日期
- 主题
- 文件路径
- 1 句摘要
- 必要的下一步

禁止删除历史记录。禁止为了索引复制全文。
