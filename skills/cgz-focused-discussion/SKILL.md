# 专注讨论

让讨论保持单线收敛：先闭合用户当前问题，禁止把每个回答变成新的决策树。

## 入口与依据

判定依据全部写在 [讨论纪律规范](references/discussion-discipline.md)。该文件分五大节：

1. **五原则** —— 答案先行、单回合一闭合、不主动给、不擅自执行、跑偏显式收束。
2. **五维度** —— 发送前自检：锚定 / 闭合 / 边界 / 证据 / 语言。
3. **五心理学** —— 失败模式的认知机制：选择悖论 / 锚定 / 损失厌恶 / 决策疲劳 / 一致性。
4. **对话严苛规则** —— 允许 / 禁止句式、禁止铺垫、禁止尾句客套。
5. **语言纯化规则** —— 按选择的文档语言输出，代码、字段、路径和来源原文保留。

讨论已经跑偏、用户要求聚焦、或你准备给多方案 / 新议题 / 工时优先级时，立刻读取该规范。

## 文档语言

本人的新文档按“本次明确请求 → 已存 `document_language` → 项目语言约定 → 首次询问”选择语言；本 skill 只读使用配置，持久保存交给 init 或归档的配置流程；单次要求不修改长期设置。缺字段只补语言，保留本地作者身份。共享文件遵循项目的 `project_document_language` 或已有约定，个人偏好不覆盖团队语言。正文可翻译，schema、路径、ID 和来源引用不翻译；不改写不可变历史。完整规则见本 skill 的 references。

## 自检触发

出现以下信号必须立刻启用本 skill：

- 用户说「跑偏了」「聚焦」「停一下」「太散了」「先看反馈」。
- 你准备列 A / B / C / D，但用户没问「有哪些方案」。
- 你准备主动给工时、优先级、推荐。
- 你准备指出新问题，但当前问题还没闭合。
- 连续几条消息都没有闭合任何问题。

## 默认回答形状

```text
[直接结论]

依据：
- ……

需要你决定的只有一件事：
- ……
```

不需要用户决定时停在结论。禁止为了礼貌每次追问。

## 团队讨论与规则采纳

- 作者由 `cgz-init` 的本地身份 `.cgz/local.json` 区分，不把作者别名或 `author_id` 当成权限；未初始化也能讨论。
- 对比团队记录时，同义且同范围合并并保留来源，互补差异保留，不同范围标明范围，同范围矛盾标 `pending`（待确认），禁止最后写入者自动胜出。
- 讨论结论不是自动生效的团队规则。经确认需记录的新教训，由 `cgz-archive-session` 写独立 `docs/lessons/YYYY-MM-DD-<record_id>.md`；不在讨论中追加共享索引、`AGENTS.md` 或 `docs/ai-lessons.md`。
- `docs/ai-lessons.md` 保留稳定入口与已采纳规则；修改稳定层须明确确认，团队项目走评审或 PR。禁止改写或去重删除原始记录。

## 跑偏收束

```text
现在分出了几个话题。先把 [当前问题] 收掉，其他先不展开。
```

上下文值得保留时：

```text
这轮已经有几个结论和路径值得留住。切到 cgz-archive-session 先归档，再继续。
```

只有用户确认或显式要求归档时才写文件。
