# 阅读输出规范

阅读必须只服务用户当前问题。本文件是判定依据，分五大节：五原则、五维度、五心理学、对话严苛规则、语言纯化规则。`SKILL.md` 是入口，处理任何阅读类任务前读这里。

---

## 一、五原则

1. **先锚定用户问题，再决定读什么。** 不锚定就读 = 读全文。
2. **不主动扩大阅读范围。** 需要额外文件时，必须说明为什么需要再读。
3. **必须区分原文事实、推断、不确定点。** 三者不可混写。
4. **旁支发现最多 3 条，放在最后不展开。** 用户未问，禁止延展。
5. **不把阅读题答成实现题。** 用户没说「改 / 实现」时，禁止给方案或工时。

---

## 二、五维度（输出前自检）

1. **范围** —— 本次读取是否在用户问题边界内，没有为了显得全面而读无关目录。
2. **证据** —— 每个结论是否带 `path:line`、命令输出或可定位的事实。
3. **区分** —— 已确认 / 推断 / 不确定是否用标签分清，没有把推断写成事实。
4. **形态** —— 输出是否匹配请求类型（结论 / 摘要 / 风险 / 对比 / 提取 / 定位）。
5. **语言** —— 中英是否混杂；英文模板字段是否保持纯英文。

---

## 三、五心理学（失败模式的认知机制）

1. **全景偏好** —— agent 倾向显示「我读全了」而非「我读对了」。读得多不等于读得准。
2. **锚定效应** —— 一旦扫到无关大段，注意力会被拽走，输出开始围绕无关材料组织。
3. **沉没成本** —— 已读的无关内容会被强行塞进输出，证明自己没白读。
4. **教学冲动** —— 把简单查询答成完整教程。用户问「在哪」时给出「为什么」会引发噪声。
5. **一致性偏差** —— 读到矛盾时倾向掩盖而非标注，让输出看起来更顺，但隐藏了风险。

---

## 四、对话严苛规则

**允许的句式**：必须 / 禁止 / 立刻 / 不得 / 只。

**禁止的句式**：优先 / 尽量 / 建议 / 可以考虑 / 也许。

**禁止的开场**：「让我先看一下整体结构」「我来通读一遍」「这是个很有意思的文档」。

**禁止的扩展**：

- 用户问「在哪定义的」时，不得附带「顺便看了 X，我觉得……」
- 用户问「这段是什么意思」时，不得展开重构建议
- 用户问「这个 PR 有没有问题」时，不得给出工时或优先级

回答以结论或位置开头，以结论或单一澄清问句结尾。

---

## 五、语言纯化规则

**中文段落不夹裸英文 token**：

- `Yes/No` → 是 / 否
- `path` → 路径
- `grep` → 检索
- `diff` → 差异
- 表达技术含义需要原词时，首次出现括注一次中文

**英文模板字段保留纯英文，不译**：

- Read first / Known facts / Open questions / Do not assume / Goal / Changed / Verified / Decisions / Risks / Next

**表格里同一格不混语言。**

**文件名、命令名、API 名、字段名、标签名一律保留原文。**

## 输出模板

### 默认回答

```markdown
**结论**
[直接回答用户问题]

**依据**
- `path:line`：[关键事实]

**不确定**
- [缺失材料或待验证点]

**附带发现**
- [最多 3 条；没有就省略整段]
```

### 摘要

```markdown
**核心摘要**
- ……
- ……
- ……

**和你问题相关**
- ……

**下一步阅读入口**
- `path`
```

### 给下一个 agent 读

```markdown
Read first:
- `path`

Known facts:
- ...

Open questions:
- ...

Do not assume:
- ...
```

## 范围控制

| 用户请求 | 必须读取范围 |
| --- | --- |
| 看这个文档讲了什么 | 只读该文档，输出核心结论 |
| 这段 PR 有没有问题 | 读 diff + 相关测试 / 调用点，不扫全仓库 |
| 帮我理解上下文 | 读用户指定上下文 + 最近相关文档，不扩到全项目 |
| 从图文 / 网页里提取信息 | 只提可见事实；细则要求时再读 reference |
| 找某个答案 / 字段 | 优先检索，直接返回位置和答案 |

长材料先扫目录、标题、索引、首尾段、代码入口；命中相关问题再深入。

---

## 图文 / 网页材料

读取图文或网页不能只看正文。必须保留来源、图片顺序、可见信息、可复用素材索引。

提取顺序：

1. **来源**：URL、标题、作者 / 账号、发布时间、抓取时间。
2. **文本**：标题、正文主张、列表、价格 / 数字 / 限制条件。
3. **图片**：每张图的可见内容、顺序、与正文的对应关系。
4. **链接 / 附件**：只记录与用户问题相关的链接。
5. **可信度**：缺失、模糊、疑似广告或无法验证的信息。

输出只放与用户问题相关的部分。完整素材清单仅在用户要求归档或复用时写入文件。

---

## PR / 代码阅读

- 先读 diff，再读被调用点和测试。
- 不扫全仓库，除非当前问题需要。
- 结论必须落到具体文件、函数、行为或测试缺口。
- 不把 review 变成重构计划。

---

## 日志阅读

- 先定位时间、错误级别、请求 / 任务 ID。
- 区分根因、症状和噪声。
- 不把没有证据的猜测写成结论。

---

## 禁止模式

- 禁止顺手提实现方案、重构建议、工时、优先级。
- 禁止把一个阅读问题拆成多轮决策树。
- 禁止把整篇材料复制给用户。
- 禁止把未读到的内容写成事实。
- 禁止为了显得全面而读无关目录。
- 用户只问「哪里写了」时，禁止输出长篇解释。
