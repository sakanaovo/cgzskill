# AI 自我进化架构

## 当前目标

把项目里的 AI 使用经验沉淀成可复用记忆，让后续 Claude / Codex 在读取项目上下文后表现得更稳定、更贴近用户习惯。

「自我进化」不是模型自动训练，而是项目级学习：

```text
对话 / 代码改动 / 文档阅读 / 错误反馈
  → 提炼事实和规则
  → 写入项目记忆
  → 下次 AI 读取
  → 行为变得更稳定
```

## 基本边界

- 禁止假设 AI 会永久记住聊天。
- 禁止把所有聊天塞进文档。
- 禁止把推测写成事实。
- 禁止让归档变成新一轮分析。
- 禁止把用户没确认的偏好固化成规则。

## 五大节骨架（贯穿五个 skill）

五个 skill 的判定依据都写在各自的 `references/`，遵循同一份骨架：

1. **五原则** —— 必须遵守的核心约束
2. **五维度** —— 发送或写入前的硬性自检
3. **五心理学** —— 失败模式背后的认知机制
4. **对话严苛规则** —— 允许 / 禁止句式
5. **语言纯化规则** —— 中文 / 英文不混杂

加新 skill 时，references 必须沿用这套五大节。

## 核心闭环

### 1. 初始化

新项目先扫描并建立项目级记忆骨架，确保后续读取、讨论、归档和复盘都有落点。

对应 skill：

- `cgz-init`

初始化只负责：

- 检查 `AGENTS.md`
- 检查 `docs/ai-lessons.md`
- 检查 `docs/archives/`
- 询问 `obsidian_vault` 配置
- 缺什么补什么，不覆盖已有文件

### 2. 读取

AI 先读取用户指定材料，只回答当前问题。

对应 skill：

- `cgz-focused-reading`

输入包括：

- 文档
- 源码
- PR / issue
- 日志
- 网页 / 图文
- 长聊天上下文

输出必须区分：

- 已确认事实
- 推断
- 未验证点
- 下一步入口

### 3. 讨论

AI 在讨论中保持单线收敛，先闭合用户当前问题，禁止主动扩展方案树。

对应 skill：

- `cgz-focused-discussion`

主要约束：

- 用户没问方案，禁止列多方案。
- 用户没问工时，禁止给工时。
- 用户没问优先级，禁止塞优先级。
- 当前问题没闭合，禁止抛新问题。
- 对话变长或变散时立刻建议归档。

### 4. 归档

对话变长、工作完成、上下文准备交接，或用户说「归档 / 收尾 / 先到这」时，把本轮上下文写进项目记忆。

对应 skill：

- `cgz-archive-session`

归档只保存：

- 当前目标
- 已确认事实
- 关键路径
- 决策记录
- 未验证点
- 下一步入口

归档禁止保存：

- 闲聊
- 重复确认
- 未确认偏好
- 大段原文
- 新增方案与额外分析

### 5. 沉淀

归档后的内容按稳定程度进入不同位置。

分层规则：

| 内容类型 | 必须位置 |
| --- | --- |
| 长期行为规则 | `AGENTS.md` / `CLAUDE.md` |
| 可复用工作流 | `skills/` |
| 单次会话记录 | `docs/archives/` 或项目已有 docs |
| 交接给下个 agent | handoff 文档 |
| 未验证想法 | 归档里的「未验证」小节 |

稳定规则才能进入 `AGENTS.md` 或 skill。一次性的上下文只进归档。

### 6. 复盘

当天结束或用户要求复盘时，把当天归档与教训聚合成 Obsidian Daily note。

对应 skill：

- `cgz-daily-recap`

复盘只做索引和当天事实聚合，禁止重新分析、补方案或跨天混写。

### 7. 复用

下一轮 AI 启动时，通过读取项目说明、skill 与 docs 恢复上下文。

复用顺序：

1. 先读 `AGENTS.md` / `CLAUDE.md`。
2. 按任务触发 skill。
3. 需要历史时读对应归档。
4. 只把与当前问题相关的记忆带回上下文。

## 自我进化触发点

适合提炼新规则：

- 用户指出 AI 跑偏。
- AI 误解「讨论」和「执行」。
- 同类问题反复返工。
- 多次需要同一套阅读 / 归档格式。
- 用户明确表达了稳定偏好。
- 某个错误有明确复现与修正方式。

禁止提炼成规则：

- 用户只是单次场景的临时选择。
- 结论没有验证。
- 只是 agent 的猜测。
- 会限制后续正常执行。

## 最小实现

当前仓库已有五块：

```text
cgz-init
  负责初始化项目记忆骨架

cgz-focused-reading
  负责读材料不发散

cgz-focused-discussion
  负责讨论不发散

cgz-archive-session
  负责把值得保留的上下文写成项目记忆

cgz-daily-recap
  负责按天聚合归档和教训
```

调用关系：

```text
读材料过长 → cgz-focused-reading 建议 cgz-archive-session
讨论跑偏 → cgz-focused-discussion 建议 cgz-archive-session
归档完成 → cgz-archive-session 只给短摘要
当天收尾 → cgz-daily-recap 聚合当日落地记录
稳定经验 → 经人确认后再写入 AGENTS.md 或 skill
```

## 验收标准

这套架构成立时必须满足：

- AI 下次能记得用户不喜欢发散式方案树。
- AI 能区分「读一下」和「去实现」。
- AI 能在上下文变长时主动建议归档。
- AI 禁止擅自把一次性偏好写成长期规则。
- 未来 agent 能通过短归档快速恢复任务。
